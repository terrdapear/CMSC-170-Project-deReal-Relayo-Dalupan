Problem and Motivation

Given two datasets, Republic Acts with Summaries and the episode transcripts of Better Call Saul, we build a binary text classifier that tells whether a piece of text it has never seen comes from a Philippine Republic Act (RA) or from a Better Call Saul (BCS) episode.

Republic Acts are formal government documents, while the transcripts are informal TV dialogue. We want to measure how different the two kinds of text are, and to compare how three machine learning methods do at classifying unseen text, in both accuracy and speed. We also look at how changing each method's parameters, like the smoothing factor in Naive Bayes or k in KNN, changes its results.

Dataset

Sources

  • Republic Acts: Republic Acts with Summaries (Parquet) from BetterGov.PH, part of their gov-library of Philippine legal documents converted from Lawphil.net.
  • Better Call Saul: the 63 episode transcripts of Better Call Saul (2015-2022) from Subslikescript.

The TV show transcripts are used only for natural language processing research. Under Section 185 of Republic Act No. 8293 (the Intellectual Property Code of the Philippines), using copyrighted works for research and scholarship is fair use. All rights to the original works stay with their copyright holders.

Samples, features and target

  • Samples: 10-word paragraphs of text.
  • Features: a bag of words for each paragraph, which is how many times each word appears in it. The training paragraphs have a vocabulary of 16,703 words (12,115 in BCS and 7,574 in RA).
  • Target: the class of the paragraph. RA is the positive class (label 1) and BCS is the negative class (label 0).

Preprocessing

  1. Parquet to text (RA, done once). The Republic Acts were converted from Parquet to one tab-separated text file (helper_scripts/parq_to_txt.py). This is the only step that uses pandas. The data loading, preprocessing and method code do not use it. The file was larger than GitHub's 100 MB limit, so RA/split.py cut it into the 3,995 files in RA/RA_split.
  2. Remove website text (BCS). We removed the first 4 lines (title and source) and the last 3 lines (footer) of each transcript (Better_Call_Saul_Transcripts/cleaner.py).
  3. Clean. We lowercased every word and removed every character outside a-z and 0-9, so "Court's" becomes "courts". Words left empty are dropped.
  4. Cut into 10-word paragraphs. Every 10 words are saved as one paragraph file. A BCS paragraph never runs into the next episode, so the last one in each episode can be shorter (Better_Call_Saul_Transcripts/cleaner.py and RA/cleaner.py).
  5. Balance. There are far more RA paragraphs, so we only keep the first 24,174 paragraphs of each class, the size of the smaller class (prepare_data_folders in scripts/preprocess.py). With balanced classes, always guessing one class only gets 50% accuracy.
  6. Bag of words. Each paragraph is turned into word counts (scripts/bow.py).

The RA paragraphs are too many files for GitHub, so they are not in the repository. The README shows how to make them from RA/RA_split.

Methods

We compare Naive Bayes, K-Nearest Neighbors (KNN) and the Perceptron. All three use the same bag of words for each paragraph, so they solve the same task with the same input. We wrote every method ourselves in Python, using only the standard library. Each method is a Python class in its own file in the scripts folder.

Naive Bayes (scripts/NB.py)

How it works: Naive Bayes learns how likely each word is to appear in RA and in BCS paragraphs. It then classifies a new paragraph by which class most likely produced its words.

How we implemented it: We follow the CMSC 170 laboratory module. The model keeps the word counts of all RA training paragraphs and of all BCS training paragraphs. The probability of a word given a class uses add-k (Laplace) smoothing:

P(word | class) = (count of the word in the class + k) / (total words in the class + k × vocabulary size)

Multiplying many small probabilities made our scores go to 0 in Milestone 2, so instead we add up their logs, based on Jurafsky and Martin. The paragraph goes to the class with the higher log score. Words that never appeared in training are skipped.

K-Nearest Neighbors (scripts/KNN.py)

How it works: KNN compares a new paragraph to every training paragraph and labels it by the majority vote of the k closest ones. Each word is one dimension, and the distance between two paragraphs is the Minkowski distance with exponent p (p = 1 is Manhattan distance, p = 2 is Euclidean distance).

How we implemented it: In Milestone 2, KNN turned every bag of words into a point with one number for every word in the vocabulary. With 38,678 training paragraphs and 16,703 words, that is about 646 million numbers, which was too slow to finish. The new version keeps each bag as a dictionary and keeps an index of which training paragraphs contain each word. It only computes the full distance for paragraphs that share a word with the test paragraph. For the rest, the distance only depends on the size of each bag, so we use a list sorted by size. The distances are exactly the same as before.

Perceptron (scripts/perceptron.py)

How it works: The Perceptron learns a weight for each word and predicts RA if the weighted sum is positive. It adjusts the weights whenever it makes a mistake.

How we implemented it: We follow the same steps as in our laboratory exercise. The two classes become desired outputs of -1 (BCS) and 1 (RA). The model computes v = sum(wi × xi) + b and outputs 1 if v > 0, and -1 otherwise. When the output y does not match the desired output d, it updates each weight using w(n+1) = w(n) + r(d - y)x, and the bias in the same way. Weights are stored in a dictionary by word, since most words do not appear in a given paragraph, and a word with no weight yet counts as 0. The training data is shuffled every epoch with a fixed seed, so the classes are mixed and the results repeat. Training stops when an epoch has no mistakes or after 20 epochs, since the data might not be linearly separable.

Experimental Setup

Data split

We read the files in sorted order and use the first 80% of each class for training and the last 20% for testing. That is 19,339 training and 4,835 test paragraphs per class, or 38,678 and 9,670 in total. We only use one split because our instructor pointed out that the split ratio can affect KNN. Since the split is not shuffled, the test paragraphs come from different episodes and acts than the training ones. For example, the BCS test paragraphs are from the last episodes in alphabetical order (Something Beautiful to Witness).

All three methods use the same paragraphs and the same preprocessing. The Perceptron shuffles its training data with seed 170, so we get the same results every run. Only the times change.

Metrics

We wrote all the metrics ourselves in scripts/metrics.py. RA is the positive class and BCS is the negative class.

Predicted RAPredicted BCS
Actual RATrue Positive (TP)False Negative (FN)
Actual BCSFalse Positive (FP)True Negative (TN)
  • Accuracy = (TP + TN) / (TP + TN + FP + FN): how many paragraphs were classified correctly.
  • Precision = TP / (TP + FP): of the paragraphs called RA, how many really were RA.
  • Recall = TP / (TP + FN): of the real RA paragraphs, how many the model found.
  • F1 = 2 × Precision × Recall / (Precision + Recall)
  • Training time and classification runtime: seconds to build the model, and seconds to classify all the test paragraphs.

Precision and recall usually trade off: calling more paragraphs RA raises recall but lowers precision, and the other way around. F1 is the harmonic mean of the two, so it is only high when both are high.

We also report a baseline that always predicts RA. It still gets 100% recall and a 66.67% F1, so a method has to beat it to show that it learned anything.

Discussion

Comparing the methods

All three methods beat the Always RA baseline (50%). Naive Bayes (k = 1) had the highest accuracy (98.73%), recall (98.68%) and F1 (98.73%), and the shortest training time (0.257 s). The Perceptron (r = 0.1, bias 0) was second with 98.43% accuracy and had the fastest classification time (0.083 s), but the longest training time (2.499 s). KNN (k = 3, p = 2) had the lowest accuracy (81.10%) but the highest precision (99.15%), and it took about 115 seconds to classify, compared to about 0.1 seconds for the other two.

Naive Bayes

All three smoothing values scored between 98.61% and 98.73%. k = 1 had the highest accuracy, recall and F1, while k = 0.1 had the highest precision (98.96%). As k got smaller, false negatives went up (64, 74, 84) and false positives went down (59, 55, 50).

Why: the two classes use very different words. Of the 16,703 words in the training paragraphs, 12,115 appear in BCS and 7,574 in RA, so only 2,986 appear in both. Naive Bayes adds up the evidence from every word in a paragraph, so 10 words are usually enough. It is also fast, since training only counts words and classifying only looks up the words in the paragraph.

Perceptron

All nine settings scored between 97.76% and 98.43%, and r = 0.1 with bias 0 scored the highest. With a starting bias of 0 or 1, r = 1 and r = 0.5 gave exactly the same results. Every setting except r = 0.1 with bias 0 made more false negatives than false positives, so precision was higher than recall.

Why:

  • Like Naive Bayes, the Perceptron gives each word a weight and adds them up, so it also does well. With r = 1 and bias 0, it was still making 22 mistakes on the training data at epoch 20, so it never found weights that classify every training paragraph correctly.
  • With a starting bias of 0, the learning rate only scales all the weights by the same amount, so it does not change which side of 0 the sum lands on. This is why r = 1 and r = 0.5 gave the same results with bias 0.
  • When the sum is exactly 0, our Perceptron outputs -1 (BCS). With r = 1 and bias 0, 48 test paragraphs had a sum of exactly 0, and 37 of them were RA. This is part of why it made more false negatives.
  • 0.1 cannot be stored exactly as a floating-point number, so with r = 0.1, sums that should be exactly 0 come out slightly above or below 0, and these paragraphs no longer all go to BCS. This, not the learning rate itself, is why r = 0.1 scored higher.

KNN

Every setting had a precision above 98.7% but a recall of only 19.42% to 62.73%, so almost all of its mistakes were RA paragraphs classified as BCS (1,802 to 3,896 false negatives, but at most 26 false positives). p = 2 scored higher than p = 1 for every k, and accuracy went down as k went up: from 81.10% to 69.82% with p = 2, and from 75.34% to 59.70% with p = 1. Training took about 0.5 seconds, but classifying took 115 to 125 seconds.

Why:

  • Ties. A 10-word paragraph shares no words with most training paragraphs, and many of those are exactly the same distance away (for example, 20 with p = 1 when neither paragraph repeats a word). So there are usually many training paragraphs tied for the k-th closest spot. Our code keeps the BCS ones first when there is a tie. For 1,204 to 1,833 test paragraphs per setting, the tie decided the answer, and most of these were RA paragraphs. This is why KNN made thousands of false negatives but almost no false positives.
  • Identical paragraphs. Our code skips training paragraphs at distance 0 (the exact same words). 276 test paragraphs have such a match, and 274 of them are RA, since Republic Acts repeat phrases like "be it enacted by the senate and house of representatives". Skipping them throws away the closest match.
  • p and k. With p = 2, a repeated word counts more, so there are fewer exact ties, which is why p = 2 did better. A larger k takes more neighbors from the tied group, so more of them are BCS, which is why accuracy went down as k went up.
  • Speed. KNN does its work at classification time: it compares each test paragraph to the training paragraphs, about 12 ms per paragraph. Naive Bayes and the Perceptron only look up the words in the paragraph.

Limitations

  • KNN ties. The KNN results above come from code that breaks ties in favor of BCS and skips identical paragraphs. We are fixing this, and the KNN results will change.
  • Metadata in the RA paragraphs. The RA file still has table columns like IDs, file paths and summary headings. About 167 of the 24,174 paragraphs we used (less than 1%) contain this.
  • Narrow RA sample. The paragraphs we used only cover acts from 1946 and 1947.
  • One run. Every setting was run once on one split.
  • Too many files. The RA paragraphs make 1,689,912 files, which is too many for GitHub, even though we only use 24,174 of them.

Possible improvements

  • Break KNN ties fairly and keep identical training paragraphs.
  • Remove the table columns from the RA text before cutting it into paragraphs.
  • Use Republic Acts from more years, not only the first ones in the file.

Conclusion

All three methods can tell a Republic Act paragraph from a Better Call Saul paragraph much better than guessing, even with only 10 words. Naive Bayes did best overall, with 98.73% accuracy, and was also fast. The Perceptron was close behind at 98.43% and was the fastest to classify. KNN was the weakest at 81.10% and by far the slowest, mostly because of how it breaks ties between equally distant paragraphs, which we are fixing next.
